公式来自此前已取得的官方op-geth v1.5.4固定提交`c739e50e35071247cf459cbcbbbfc4cf989b4c57`：

```
执行费 = 最终gas用量 × 实际每gas价格
运营方费 = 最终gas用量 × operatorFeeScalar × 100 + operatorFeeConstant
网络费 = 执行费 + 收据l1Fee + 运营方费
```

全部采用整数最小单位；1 MNT对应10^18个最小单位，只用于展示。收据l1Fee在已核源码里已包含比率转换，不能再乘tokenRatio；operator的gas上限预扣差额会退款，不能拿预扣额当最终实付。原字段常数为零也不代表运营方费用整体为零。[运营费源码](https://github.com/mantle-xyz/op-geth/blob/c739e50e35071247cf459cbcbbbfc4cf989b4c57/core/types/rollup_cost.go#L437)、[退款源码](https://github.com/mantle-xyz/op-geth/blob/c739e50e35071247cf459cbcbbbfc4cf989b4c57/core/state_transition.go#L1050)、[L1收据赋值](https://github.com/mantle-xyz/op-geth/blob/c739e50e35071247cf459cbcbbbfc4cf989b4c57/core/state_processor.go#L240)。

本轮还有一个容易造成误算的字段：265个回执的blobGasUsed虽非零，实际交易类型只有legacy／type2。固定源码明确在Jovian分支把该字段复用于数据占用，不能据字段名误判为type3，再加第四笔收费。全265均有对应DA scalar且没有blobGasPrice；原生meta前缀检查也与固定输入绑定。[序列化源码](https://github.com/mantle-xyz/op-geth/blob/c739e50e35071247cf459cbcbbbfc4cf989b4c57/internal/ethapi/api.go#L1957)、[本地语义记录](root/fee-semantics-source-note.md)。

浏览器提示只显式写含operator，不能从提示文字提前认定L1口径；**三账精确一致是本次实际检验的结果**。原HTML保留格式标签和原字段；先前解析外层span混入美元按钮文本，仅在预检阶段修正为读取真实费用子span，未更改原文或重取来源。三账结果见[精确对照](execute-owner/three-bill-comparison.json)。

## 3. 这对“能不能赚钱”意味着什么

此前确认的119笔同清算之后、相同抵押代币转给E的收款事实仍成立；涉及9个发币合约，另有F21收款不能自动归E。本轮新增的是可复核的网络成本一侧，没有把收款次数当盈利次数。

现在的经济问题可以更具体地表述为：**E获得的资产与其他经济收入，按一致范围和可实现价值计算，是否超过网络收费以及兑换、融资、竞争付款和其他成本？** 网络费22.554062325826942023 MNT不能直接减去mETH、FBTC或其他代币的数量，当前市场价也不能冒充当时可兑现成交价。

这些原件没有证明全部资本、此前库存、原生币内部流、外部报销或补贴，也没有完成所有业务共同成本分摊。因此表中称网络毛收费，不能直接当最终个人经济负担或完整策略成本。8笔部署也不能一概全部归到X的清算策略，3笔外部入账不能自动认定为所有者资本。

对个人的可复制性，目前明确能复用的是公开记录核验、完整纳入失败成本和按币种记账的方法；执行工具权限、机会获取与竞争速度、全部成本后的持续优势、资金容量仍未证实。网络费用可量化不等于这些门槛已解决。不能据本轮外推到Gerko财富1%的时间或本金规模。

## 4. 下一项只读求证

**下一关键问题收敛到资产端净账，而不是再开价格模型。** 先用已存119笔逐事件原件，确定每种代币的实际收款数量、所需偿还／转出是否已经反映在执行路径，以及能否接到同口径资金流和历史可兑现价格。先制定完整的归属和估值口径，再开展金额核算，不用不完整的“收款×现价”制造利润。

完整一致估值的期初末净资产减所有者净投入，在原则上可以核定对应范围历史损益，不要求必须取得私人选单规则；但目前材料未闭合，不能把运营收入误列为资本。若缺少必要状态或原账，应明确缺口，不把未知当零、不删除失败与其他业务成本，也不因此抹去已发生收款。

本轮只完成网络账，尚未执行上述代币数量、估值或净额求证。新增模型／训练／回测／账户／交易仍不在范围内。
